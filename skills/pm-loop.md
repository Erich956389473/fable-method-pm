# pm-loop — 自适应产品执行循环

## 输入

- `decision`：pm-method 输出的决策路径
- `risk`：风险等级（可选，默认: mid，可选值: low / mid / high）
- `stage`：产品阶段（可选，默认: growth，可选值: 0-1 / growth / mature）
- `audience`：输出受众（可选，默认: self，可选值: boss / team / self）
- `deadline`：截止时间（可选）

### 参数校验规则

- 未提供可选参数时，使用默认值
- 参数值不在可选值列表中时，使用默认值并在输出中附带警告：`⚠️ 参数 "{name}" 的值 "{value}" 不合法，已使用默认值 "{default}"`
- `decision` 为空或未提供时，输出错误提示：`❌ 缺少输入 "decision"，请先运行 pm-method 获取决策路径`

## 自适应逻辑

### 1. 证据收集 — 根据产品阶段

**0-1 阶段：**
- 收集清单：用户访谈 3-5 人 + 竞品分析
- 不接受纯数据方案（没有数据）
- 时间盒：1 周内完成

**Growth 阶段：**
- 收集清单：数据看板 + 用户反馈 + 竞品
- 最少 2 类证据
- 时间盒：2 周内完成

**Mature 阶段：**
- 收集清单：AB测试 + 用户调研 + 数据模型
- 需要统计显著性
- 时间盒：1 个月内完成

**电商证据补充：**
- 选品阶段：竞品价格追踪、销量数据、库存周转率
- 促销阶段：历史大促数据、优惠券核销率
- 物流阶段：履约时效、退货率分布

### 2. INTENT 格式 — 根据受众自适应

**给 boss 看：**
```
INTENT（精简版）：
  问题：一句话
  决定：一个方案
  预期：一个数字
```

**给 team 看：**
```
INTENT（完整版）：
  问题：背景 + 现状
  证据：数据 + 用户声音
  决定：方案 + 验收标准
  风险：什么情况下停
  时间：时间线
```

**给自己看：**
```
INTENT（速记版）：
  做什么？
  凭什么？
  什么时候完？
```

### 3. 执行节奏 — 根据紧急程度

**Critical：**
- 跳过计划，直接执行
- 每 30 分钟同步一次
- 止血后再复盘

**Urgent：**
- 简化计划，最快路径交付
- 每日同步
- 交付后再补完整文档

**Normal：**
- 标准流程
- 周同步
- 完整文档

### 4. 验证深度 — 根据风险等级

**Low risk：**
- 上线即算验证
- 观察 3 天无异常即可

**Mid risk：**
- AB测试或前后对比
- 观察 1-2 周

**High risk：**
- 灰度发布 + AB测试
- 观察 1 个月 + 统计显著性验证
- 回滚方案准备

## 输出格式（供下游技能使用）

pm-loop 执行完成后，输出以下结构化信息供 pm-judge 消费：

```
## 执行结果
- 决策：[原始决策描述]
- 执行状态：[已完成 / 进行中 / 阻塞]
- 假设验证记录：
  - 假设A：[已验证 / 已证伪 / 待验证] — [证据来源]
  - 假设B：[已验证 / 已证伪 / 待验证] — [证据来源]
- 关键数据：[指标名称: 数值]
- 风险信号：[发现的风险或异常]
```

## 失败回退机制

当假设验证失败次数达到 pm-method 定义的失败阈值时：

1. **自动触发**：输出 `🔄 已达到失败阈值（{N}次），建议返回 pm-method 重新定义问题`
2. **携带上下文**：将失败记录作为输入传递给 pm-method，格式：
   ```
   problem: [原始问题]
   previous_failures: [失败假设列表]
   trigger: threshold_reached
   ```
3. **重新分类**：pm-method 基于失败记录重新评估问题分类和路径
