# pm-loop — 产品执行循环

## 输入

pm-method 输出的决策路径（或直接输入一个确定要执行的任务）

## 输出

可执行的任务计划 + 执行记录 + 偏差预警

## 核心流程

```
决策路径 ──► 证据收集 ──► 提交计划 ──► 执行 ──► 验证 ──► 复盘
                     │                             │
                     └── 确认后执行 ──────────────┘
```

## 6 个步骤

### 步骤 1：证据收集计划

自动生成需要收集的信息清单：

| 证据类型 | 收集方式 | 时间 |
|---------|---------|------|
| 用户声音 | 访谈/问卷/客服记录 | 先做（快速定性） |
| 行为数据 | 后台埋点/BI报表 | 配合定性发现 |
| 竞品动态 | 公开信息/行业报告 | 并行收集 |
| 技术评估 | 跟研发沟通 | 用于评估可行性 |

**硬约束：**
- 至少收集 2 类证据才能做决策（避免单一偏见）
- 用户定性 + 数据定量 必须搭配

### 步骤 2：提交计划（INTENT 格式）

任何执行计划必须包含以下 4 个要素：

```
INTENT 格式：
┌─────────────────────────────────────┐
│ 问题：我们要解决什么                │
│ 证据：为什么现在是时候做            │
│ 决定：具体怎么做 + 验收标准          │
│ 风险：什么情况下应该停下来          │
└─────────────────────────────────────┘
```

**硬约束：**
- 计划首次遇到模糊范围 → 停下来等待确认
- 如果问题、证据、决定、风险中任何一项是空 → 不通过

### 步骤 3：执行

按优先级拆分执行：

- 第一优先级：核心假设验证（最快最低成本验证最关键假设）
- 第二优先级：最小可行交付（对用户产生价值的最小集）
- 第三优先级：迭代优化（基于数据和反馈持续改进）

**硬约束：**
- 同一时间只推进 1-2 个关键方向
- 每个方向必须有明确的"停止条件"
- 3 次关键假设失败 → 回到 pm-method 重新定义问题

### 步骤 4：验证

每个执行项交付后必须回答：

```
1. 我们做对了什么？（跟预期一致的部分）
2. 我们做错了什么？（跟预期偏离的部分）
3. 我们不知道什么？（未解决的疑问）
4. 下一步做什么？（基于这个结果的调整）
```

### 步骤 5：决策日志

每次执行结束输出决策日志：

```
## 决策日志：2026-07-21

问题：用户积分体系
分类：🛠️ 执行型
INTENT：
  问题：提升用户留存率（首月留存从 30% 到 45%）
  证据：留存漏斗显示第 7 天流失最严重，用户反馈"没有动力"
  决定：上线积分+签到功能，MVP 3 周交付
  风险：如果 2 周没有看到留存改善，重新评估

执行状态：进行中（第 2 周）
当前发现：
- 签到功能使用率 60%，但积分兑换率仅 10%
- 假设：用户不知道积分可以兑换什么 → 加引导
- 验证：A/B 测试引导后的兑换率变化

置信度：中
未解决：积分体系对长期留存（60天+）的影响需要更长时间观察
```
