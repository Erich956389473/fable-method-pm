# pm-method — 产品思考框架

## 输入

一个产品相关的问题、需求或场景描述

## 输出

分类结果 + 处理路径 + 硬性约束

## 核心流程

```
输入问题 ──► 分类 ──► 定义完成标准 ──► 收集证据 ──► 决策 ──► 输出路径
```

## 6 步分类决策树

### 第一步：分类

收到问题后，先判断属于哪一类：

```
问题 ──► 琐碎？(< 1天工作量，无需调研)
  ├── 是 → 直接做，2 句话报告结果
  │
  └── 否 → 属于哪一类？
        ├── 🔍 调研型：需要数据/用户反馈才能回答
        │   例："用户为什么在支付页流失？"
        │   → 先收集证据，再给结论
        │
        ├── ⚖️ 决策型：有多个选项需要选
        │   例："方案A还是方案B？"
        │   → 列出选项、评估标准、评分、建议
        │
        ├── 🛠️ 执行型：确定要做，怎么落地
        │   例："我们要做个积分体系"
        │   → 拆解任务、排优先级、定验收标准
        │
        ├── ✅ 验证型：做了之后有没有效果
        │   例："改版后转化率提升了吗？"
        │   → 定义指标、收集数据、对比 baseline
        │
        └── 📈 增长型：已经稳了，怎么更好
            例："还能怎么提升 GMV？"
            → 分析瓶颈、提假设、排实验
```

### 第二步：定义完成标准

每个分类的输出必须满足对应的完成标准：

| 分类 | 完成后长什么样 | 硬约束 |
|------|--------------|--------|
| 🔍 调研 | 一条明确结论 + 支撑证据链 | 必须有至少 2 个独立证据来源 |
| ⚖️ 决策 | 选项对比表 + 推荐选项 | 如果无法区分选项 → 提实验建议 |
| 🛠️ 执行 | 任务拆解 + 优先级 + 风险标注 | 不排超过 3 个 Sprint 的内容 |
| ✅ 验证 | 指标前后对比 + 置信度标注 | 样本量不足时要标注 |
| 📈 增长 | 瓶颈分析 + 假设列表 + 实验优先级 | 每个假设必须有可量化的预期 |

### 第三步：硬性约束

```
约束 1：3 个假设被证伪 → 建议重新定义问题
  - 如果在调研/决策过程中，连续 3 个核心假设被否定
  - 不是继续找第 4 个，而是停下来问"问题本身对不对"

约束 2：2 次查找无果 → 缩小范围
  - 如果搜了 2 次都没找到相关数据/信息
  - 不是继续搜，而是缩小问题范围再试

约束 3：无法命名验证方法 → 问一个精准问题
  - 如果想不到怎么验证这个结论
  - 不是硬给结论，而是说"我还不确定，需要先确认X"

约束 4：不要过度承诺
  - 如果知识不足以回答，明确说出来
  - 标注置信度：高/中/低
```

### 使用示例

**输入：**
```
用户反馈"你们的产品太难用了，我看不懂数据"
```

**思考过程：**

```
第一步分类：
- 琐碎？不是，这涉及产品体验和用户认知 → 归类为 调研型

第二步定义完成标准：
- 需要找到：用户卡在哪里、什么程度、多少人受影响

第三步收集证据：
- 查用户访谈记录 / 查后台埋点 / 查客服工单

第四步决策：
- 如果数据支撑：输出问题定位 + 修复建议
- 如果数据不足：输出需要补充的数据 + 收集计划
```

**输出：**

```
分类：🔍 调研型
置信度：中（需要更多数据验证）

初步发现：
1. 60% 的新用户在首周内没有完成核心操作
2. 客服工单中"看不懂"是 Top 3 关键词
3. 平均使用时长低于同类产品 40%

建议：
- 优先做 5 个用户回访（定性验证这 3 个发现）
- 同时看后台埋点中每一步的流失率（定量定位节点）
- 2 周内输出完整调研报告

⚠️ 当前置信度低，因为只有后台数据没有用户声音
```
