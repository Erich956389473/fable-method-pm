# pm-method — 自适应产品思考框架

## 输入参数

- `problem`：问题描述（必填）
- `industry`：行业（可选，默认通用 / saas / ecommerce / content / finance / education）
- `stage`：产品阶段（可选，默认通用 / 0-1 / growth / mature）
- `risk`：风险等级（可选，默认mid / low / mid / high）
- `audience`：输出受众（可选，默认self / boss / team / self）
- `urgency`：紧急程度（可选，默认normal / normal / urgent / critical）

## 自适应逻辑

### 1. 分类树 — 根据行业自适应

**如果行业是 saas：**
- 获客：新增用户渠道、CAC优化
- 留存：激活率、续费率、Churn分析
- 变现：定价策略、套餐设计、扩展收入
- 产品：功能需求、技术架构决策

**如果行业是 ecommerce（电商）：**
- 选品：品类规划、SKU管理、供应商
- 流量：渠道分析、投放效率、自然搜索
- 转化：漏斗分析、页面优化、购物车
- 履约：库存、物流、售后
- 促销：大促策略、优惠券、满减

**如果行业是 content（内容/社区）：**
- 内容：创作生态、质量把控、推荐策略
- 互动：社区氛围、社交机制
- 增长：裂变、拉新
- 变现：广告、订阅、打赏

**如果行业是 finance（金融）：**
- 安全：风控、合规、反欺诈
- 交易：费率、产品设计
- 增长：渠道、用户生命周期

### 2. 证据策略 — 根据产品阶段自适应

**如果阶段是 0-1：**
- 证据以定性为主（用户访谈、竞品分析）
- 不接受无用户验证的假设
- 最小证据量：3个用户反馈

**如果阶段是 growth：**
- 定性+定量结合（后台数据+用户访谈）
- 至少2类独立证据
- 最小证据量：数据趋势+用户定性

**如果阶段是 mature：**
- 以定量为主（数据指标、AB测试）
- 需要统计显著性验证
- 最小证据量：p<0.05或有明确baseline对比

### 3. 失败阈值 — 根据风险等级自适应

**如果风险等级是 low（调个按钮颜色、改文案）：**
- 1次假设失败 → 换方案
- 不需要完整验证流程

**如果风险等级是 mid（常规功能迭代）：**
- 3次假设失败 → 重新定义问题（默认）
- 每次失败后做简短复盘

**如果风险等级是 high（定价调整、核心架构变更）：**
- 5次假设失败 → 停止并有管理者介入
- 每次失败后输出完整复盘报告
- 需要多方确认才能继续

### 4. 输出格式 — 根据受众自适应

**如果受众是 boss（老板）：**
- 输出 1 页摘要
- 格式：核心结论→数据支撑→建议→风险
- 不做详细过程展示

**如果受众是 team（团队）：**
- 输出完整分析
- 格式：问题定义→证据链→决策逻辑→执行计划
- 含详细数据和推理过程

**如果受众是 self（自己）：**
- 输出快速笔记
- 格式：结论+关键证据+下一步
- 不做格式优化

### 5. 置信度 — 根据证据质量自适应

| 证据组合 | 置信度 |
|---------|:------:|
| 用户访谈 + 数据验证 + 竞品对标 | 高 |
| 数据验证 + 竞品对标 | 中高 |
| 用户访谈 + 竞品对标 | 中 |
| 仅有数据分析或仅有用户访谈 | 中低 |
| 纯推理/假设 | 低 |

### 6. 执行顺序 — 根据紧急程度自适应

**如果紧急程度是 critical（服务挂了、安全事故）：**
- 先执行后验证 → 先止血再复盘
- 跳过完整分类流程，直接进入执行

**如果紧急程度是 urgent（本周必须上线）：**
- 简化收集环节 → 基于已有信息快速决策
- 给明确的时间盒约束

**如果紧急程度是 normal（常规需求）：**
- 标准流程：分类→收集→验证→决策
- 无时间盒约束

## 多问题拆解（新增能力）

对于复杂的跨类问题（如"提升GMV"），自动拆解为多个子问题：

```
输入：提升电商 GMV
拆解：
├── 流量问题（渠道优化、投放效率）
├── 转化问题（漏斗优化、页面体验）
├── 客单价问题（捆绑销售、推荐策略）
└── 复购问题（会员体系、复购激励）

每个子问题独立走自适应流程
```

## 使用示例

**输入：**
```
problem: 用户在支付页流失率从 15% 涨到 25%
industry: ecommerce
stage: growth
risk: mid
audience: team
urgency: normal
```

**输出（节选）：**

```
分类：转化型（基于电商行业）
证据策略：数据+用户定性（基于 growth 阶段）
阈值：3次假设失败→重定义（基于 mid 风险）
输出：完整团队版报告（基于 team 受众）

核心路径：
步骤1：确认流失发生在支付页的哪一步
  - 看漏斗：选择支付方式→填写信息→确认支付
步骤2：找原因
  - 假设A：新增支付方式导致用户困惑
  - 假设B：页面加载变慢
  - 假设C：流程变长了一步
步骤3：验证
  - 最先验证影响面最大的假设（数据说话）
```
