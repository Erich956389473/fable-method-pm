# pm-judge — 自适应产品验证器

## 输入

- `decision`：待验证的决策/假设（必填）
- `decisionType`：决策类型（可选，默认: feature，可选值: pricing / strategy / experiment / ecommerce）
- `risk`：风险等级（可选，默认: mid，可选值: low / mid / high）
- `audience`：输出受众（可选，默认: self，可选值: boss / team / self）
- `evidence`：已有证据（可选）

### 参数校验规则

- 未提供可选参数时，使用默认值
- 参数值不在可选值列表中时，使用默认值并在输出中附带警告：`⚠️ 参数 "{name}" 的值 "{value}" 不合法，已使用默认值 "{default}"`
- `decision` 为空或未提供时，输出错误提示：`❌ 缺少必填参数 "decision"`

## 自适应逻辑

### 1. 对抗强度 — 根据决策类型

**Feature 决策（功能迭代）：**
- 替代解释数量：2 个
- 验证方法：AB测试或前后对比
- 接受标准：p<0.05 或明确趋势

**Pricing 决策（定价调整）：**
- 替代解释数量：4 个
- 验证方法：多组AB测试 + 用户调研
- 接受标准：p<0.01 + 定性验证

**Strategy 决策（战略方向）：**
- 替代解释数量：5 个
- 验证方法：多方验证 + 外部数据 + 专家评审
- 接受标准：多个独立证据来源一致

**Experiment 决策（实验）：**
- 替代解释数量：1 个
- 验证方法：快速验证
- 接受标准：有方向性信号即可

**E-commerce 决策（选品/定价）：**
- 替代解释数量：3 个
- 验证方法：小范围 A/B 测试 + 历史数据对比
- 接受标准：有统计显著性 + 毛利影响评估

### 2. 假设跟踪 — 自动分类

不是所有假设都值得跟踪到天荒地老。根据重要程度分类：

**P0 假设（核心假设）：**
- 如果不成立，整个方案作废
- 跟踪到被验证或证伪为止
- 需要汇报给决策者

**P1 假设（重要假设）：**
- 如果不成立，方案需要调整
- 跟踪 3 轮验证
- 记录结论即可

**P2 假设（优化假设）：**
- 如果不成立，不影响核心方案
- 验证 1 次即可
- 结论记录到笔记

### 3. 输出格式 — 根据受众

**Boss：**
```
## 验证摘要
结论：✅ 建议继续 / ❌ 建议停止
关键证据：[1句话]
风险：[1句话]
```

**Team：**
```
## 验证报告
### 核心结论
### 验证过程
### 替代解释
### 悬而未决
### 建议
```

**Self：**
```
没通过？→ 原因
通过了？→ 下步
```

## 输出格式（决策日志 — 闭环输出）

pm-judge 作为验证环节，输出最终决策日志，完成 Think → Act → Prove 闭环：

```
## 决策日志
- 决策：[决策描述]
- 决策类型：[feature / pricing / strategy / experiment / ecommerce]
- 验证结论：✅ 建议继续 / ❌ 建议停止 / ⚠️ 需补充证据
- 置信度：[高/中高/中/中低/低]

## 假设跟踪
| 假设 | 优先级 | 状态 | 证据来源 |
|------|--------|------|----------|
| [假设1] | P0/P1/P2 | 已验证/已证伪/待验证 | [来源] |

## 替代解释
- [替代解释1] — [是否被排除]
- [替代解释2] — [是否被排除]

## 悬而未决
- [未解决的问题]

## 建议
- [下一步行动]
```

## 与 pm-loop 的联动

- 当 pm-judge 验证结论为 ❌ 时，pm-loop 应触发失败回退机制
- 当假设证伪次数达到阈值时，自动携带上下文返回 pm-method
