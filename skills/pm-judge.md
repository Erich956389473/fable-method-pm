# pm-judge — 产品验证器

## 输入

pm-method 或 pm-loop 的输出（或任何决策/假设）

## 输出

验证报告：假设状态、置信度、未解决的疑问、建议

## 核心原则

**"每个结论都有别的解释。找到它。"**

## 验证流程

### 第一步：对抗性质疑

对每个结论，主动提出相反假设：

```
结论：改版后转化率从 5% 提升到 8%

对抗性质疑：
❓ 有没有可能是因为季节性因素？（双11期间自然增长）
❓ 有没有可能是因为样本偏差？（新用户 vs 老用户比例变化）
❓ 有没有可能是因为其他改动？（同一时间还改了别的）
❓ 有没有可能是测量误差？（埋点代码写错了）
```

**硬约束：**
- 每个结论至少提出 2 个替代解释
- 如果不能排除替代解释 → 置信度降级

### 第二步：假设跟踪

维护一张假设跟踪表：

| 假设 | 状态 | 证据 | 置信度 | 验证日期 |
|------|:----:|------|:-----:|---------|
| 改版提升转化率 | ✅ 验证 | A/B测试 p<0.05 | 高 | 7/21 |
| 用户需要积分体系 | ⚠️ 待验证 | 访谈5人中3人提到 | 中低 | - |
| 竞品不会跟进 | ❌ 证伪 | 竞品已上线相同功能 | 低 | 7/20 |

**状态定义：**
- ✅ 验证：有足够证据支持的假设
- ⚠️ 待验证：有初步证据但不够充分
- ❌ 证伪：被数据或事实否定的假设
- 🔄 在验证：正在收集数据

**硬约束：**
- 3 个假设被证伪 → 建议回到 pm-method 重新定义问题
- 长期未验证的假设 → 标记为"低优先级"或"重新评估"

### 第三步：输出验证报告

```
## 验证报告

### 本次验证的结论
1. ✅ 首页改版提升了转化率（置信度：高）
   - A/B 测试：对照组 5.2% → 实验组 8.1%
   - 统计显著性：p<0.05
   - 已排除：季节性因素（对比上月同期增幅 0.3%）、
     样本偏差（新旧用户比例一致）

2. ❌ 用户想要更多颜色选项（置信度：证伪）
   - 原假设：颜色多了用户会更满意
   - 实际结果：4 种颜色 vs 12 种选择 → 满意度无差异
   - 结论：不是颜色问题，是选择疲劳

### 悬而未决
- 改版对长期留存的影响（需要 60 天数据）
- 移动端的适配效果（测试覆盖率不够）

### 建议
- 优先跟进首页改版的长期留存数据
- 暂停颜色选项的需求
- 补测移动端覆盖
```
