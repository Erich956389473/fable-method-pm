# Fable Method for PMs — 自适应版

**Think / Act / Prove — 不再是固定模板。输入场景，自动调整。**

## 和原版 fable-method 的区别

| | fable-method（原版） | Fable Method for PMs |
|---|---|---|
| 领域 | 软件工程 | **产品管理** |
| 核心输出 | 代码+测试 | **决策+验证** |
| 模板 | 固定 | **自适应（6个维度可调）** |
| 语言 | 英文 | **中文** |
| 技能数 | 4个 | **3个** |

## 自适应维度一览

| 维度 | 可调参数 | 影响 |
|------|---------|------|
| 分类树 | **industry** | SAAS/电商/内容/金融/教育 → 不同分类 |
| 证据策略 | **stage** | 0-1侧重定性，成熟期侧重定量 |
| 失败阈值 | **risk** | 低风险1次就换，高风险5次才停 |
| 输出格式 | **audience** | 给老板1页摘要，给团队完整报告 |
| 置信度 | 证据组合 | 用户访谈+数据→高，纯推理→低 |
| 执行顺序 | **urgency** | 紧急先执行后验证，常规标准流程 |
| **新增** | 多问题拆解 | 复杂问题自动拆成子问题独立处理 |

## 技能

| 技能 | 功能 | 自适应维度 |
|------|------|-----------|
| **pm-method** | 分类问题+定义路径 | industry, stage, risk, audience, urgency |
| **pm-loop** | 执行+跟踪 | stage, risk, urgency, deadline |
| **pm-judge** | 验证+质疑 | decisionType, risk, audience |

## 数据流与回退机制

```
pm-method → pm-loop → pm-judge
    ↑           ↑           │
    │           │           │
    │     失败达到阈值       │
    └───────────┘           │
    ↑                       │
    └─────── 验证结论 ──────┘
```

- pm-method 输出结构化决策路径，供 pm-loop 消费
- pm-loop 执行后输出假设验证记录，供 pm-judge 消费
- pm-judge 输出决策日志，完成闭环
- 当假设失败次数达到阈值时，自动回退到 pm-method 重新定义问题

## 参数校验

所有技能遵循统一的参数校验规则：
- 未提供可选参数 → 使用默认值
- 参数值非法 → 使用默认值 + 输出警告
- 必填参数缺失 → 输出错误提示

## 用法示例

```
# 电商增长期 PM 遇到支付流失问题
pm-method
  problem: 支付页流失率从15%涨到25%
  industry: ecommerce
  stage: growth
  risk: mid
  audience: team
  urgency: normal

# 输出不再是固定模板，而是根据你的场景动态调整
```

## 设计原则

1. **场景决定流程** — 行业不同分类不同，阶段不同证据不同
2. **风险决定深度** — 低风险快速执行，高风险步步为营
3. **受众决定格式** — 给老板看结论，给团队看过程
4. **证据决定置信度** — 不说"我觉得"，说"数据表明"
