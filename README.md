# Fable Method for PMs

**Think / Act / Prove — 像优秀 PM 一样思考。**

借鉴 fable-method 的 Think/Act/Prove 三循环结构，但专为产品管理设计。
不是教你怎么用 AI，而是教 AI 怎么像优秀 PM 一样决策。

## 和原版 fable-method 的区别

| | fable-method（原版） | Fable Method for PMs |
|---|---|---|
| 领域 | 软件工程/编码 | **产品管理** |
| 核心输出 | 代码+测试 | **决策+验证** |
| 验证方式 | 测试通过/失败 | **假设验证/证伪** |
| 硬约束 | 3次测试失败→停止 | **3个假设证伪→重新定义问题** |
| 语言 | 英文 | **中文** |
| 技能数 | 4个 | **3个** |

## 技能

| 技能 | 做什么 | 输入 | 输出 |
|------|--------|------|------|
| **pm-method** | 思考：分类问题、定义标准、收集证据 | 一个产品问题 | 分类 + 处理路径 |
| **pm-loop** | 执行：收集证据→提计划→执行→验证 | 决策路径 | 决策日志 + 执行记录 |
| **pm-judge** | 验证：对抗性质疑、假设跟踪、输出报告 | 决策/假设 | 验证报告 |

## 怎么用

在任何支持 SKILL.md 的 Agent 中使用：

```
遇到产品问题时，先用 pm-method 分类：
"用户说签到功能没用，怎么回事？"
→ pm-method 会分类（调研/决策/执行/验证/增长）
→ pm-loop 生成执行计划
→ pm-judge 验证每个假设
```

## 设计原则

1. **好流程比好模型重要** — 优秀 PM 不是因为聪明，而是因为有科学的决策流程
2. **证据驱动** — 每条规则存在是因为没有它的时候出过问题
3. **诚实** — 不知道就说不知道，标注置信度
4. **可验证** — 每个决策都能追溯证据链
